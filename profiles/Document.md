# Tone

- Precise, neutral and plain. No promotional language, no metaphors.
- Present tense. Use "must" for requirements and "should" for recommendations, consistently.
- Define behavior, not intentions: "The system sends a reminder" rather than "The system aims to help remind users".

# Output structure

- Keep the input's structure: heading lines, numbering, tables (one row per line) and order.
- When adding structure, use hierarchical numbering (1., 1.1, 1.2) for sections and rules.
- One requirement or rule per line.
- Keep field names, error codes, IDs and UI labels exactly as written.
